# GIS 空间工作台视觉改造指南

> 文档类型：How-to Guide  
> 目标读者：负责修改现有 GIS 原型的前端 / UI Agent  
> 目标：在不改变业务架构、业务流程和数据规则的前提下，将参考图的清爽、低噪声地图视觉迁移到现有 GIS 空间工作台。  
> 范围：仅覆盖 GIS Map View 的视觉系统、布局几何、组件表现、交互状态、可访问性与前端性能。  
> 不在范围：Building View、Task View 的业务重构，后端、数据库、权限、部署、业务字段、业务状态规则和新增业务能力。

## 1. 开始前先锁定边界

本次工作是视觉改造，不是产品重构。默认保留现有 GIS 的信息架构、入口关系和交互能力，只迁移参考图中可复用的色彩、空间、层级、表面和地图表达方法。

实施前必须确认以下不变量：

- GIS 空间工作台仍是平台首页。
- 一级平台顶栏保持 64px，继续承载品牌、智能搜索、任务中心、消息和用户区。
- 不恢复固定左侧功能导航。
- 图层面板仍由地图上的“图层”按钮打开，并以左侧覆盖面板呈现，不推动地图。
- 地图点击对象仍是默认行为，不新增指针、框选或测量模式。
- 地图常驻工具只保留图层、放大、缩小、定位和复位视角。
- 选中房屋幢后，右侧对象面板仍是该对象的唯一操作中心；不新增底部操作条，也不在地图信息浮层中复制业务操作。
- 分层分户图和实测替换预测仍从当前幢对象上下文进入；深链参数、当前幢、地图视角和返回恢复行为不得变化。
- 房屋幢、其他构筑物、道路、绿化、宗地边界、门牌和建筑编号仍由真实图层开关控制。
- 默认视角、Z16 / Z17 / Z18、定位和复位必须真实改变 SVG 视图，不能用提示消息代替。
- 离线底图必须保留“演示底图 · 非测绘成果”提示。
- 所有演示值继续明确标为模拟数据；不得虚构上线结果、业务指标或业务闭环。

## 2. 视觉参考不等于业务需求

参考图提供的是视觉方向，不是需求文档，也不是字段字典。截图中的信息由生成式方式制作，只能用于观察构图和风格，不能作为产品事实。

### 可以迁移

- 低饱和、浅色、减少地图噪声的底图处理。
- 白色悬浮表面与克制阴影形成的前后层级。
- 蓝色作为唯一主要交互强调色。
- 选中对象的半透明填充、清晰描边和定位标记组合。
- 搜索、图层和地图工具的紧凑几何与一致控件语言。
- 通过留白、字重和位置区分层级，而不是依赖大量边框。

### 不可以直接迁移

- 截图左侧的固定功能导航。它与现有“无固定左栏”的空间工作台架构冲突，未经用户明确批准不得恢复。
- 截图中的地块 ID、容积率、用地性质、地名、指标、图层名称或任何其他字段和值。
- 截图中的“3D”按钮、图层透明度调节或其他现有原型未提供的能力。
- 截图表现出的数据关系、菜单归类、选中对象类型和业务操作路径。
- 为了接近截图而把房屋幢操作从右侧对象面板迁移到气泡、左栏或底部工具条。

如果视觉参考与当前基线发生冲突，以当前基线和已实现行为为准。无法判断时停止扩展，只做不改变语义的样式调整。

## 3. 参考图的设计要点

| 观察维度 | 参考图表现 | 在现有系统中的迁移方式 |
| --- | --- | --- |
| 整体氛围 | 浅色、低对比、较大留白 | 降低底图饱和度和非任务要素对比度，保持业务对象清楚 |
| 强调色 | 单一中蓝贯穿选中、勾选和链接 | 继续使用现有 TDesign 主色 `#0052D9`，不另造品牌蓝 |
| 表面层级 | 搜索、信息浮层、图层面板均为白色悬浮面 | 统一面板背景、边界、圆角和阴影，避免玻璃拟态 |
| 地图对象 | 选中区域有蓝色半透明填充、描边与锚点 | 应用于当前选中房屋幢，不能覆盖已有业务状态色 |
| 控件密度 | 单个控件紧凑，控件组之间留白明确 | 使用 32 / 36 / 40px 控件高度与 8 / 12px 组间距 |
| 图标 | 线性、统一尺寸、低装饰 | 复用同一 SVG 图标体系，禁止混用 emoji、字符图标和多套线宽 |
| 信息层级 | 标题、正文、弱标签层次清楚 | 采用既有 12 / 14 / 16 / 20 / 30px 语义字阶 |
| 地图可读性 | 水体、绿化、道路、建筑低饱和分层 | 保持图层可辨，同时让选中对象和业务面板成为第一视觉焦点 |

参考图的精致感主要来自“少颜色、少边界、稳定间距、明确焦点”，不来自添加更多卡片或装饰。

## 4. 推荐迁移策略

采用“保留骨架，替换皮肤，逐层验证”的策略：

1. 冻结现有 DOM 语义、路由参数、图层开关逻辑、对象选择逻辑和返回恢复逻辑。
2. 在既有 TDesign 变量之上补齐 GIS 语义变量，不建立脱离 `screen/workspace-tdesign.css` 的第二套主题。
3. 先统一地图底图和悬浮表面，再处理搜索、工具、图层抽屉、对象选中与信息浮层。
4. 用视觉回归验证所有已实现状态，再做小范围动效和性能优化。
5. 只有在用户另行批准后，才讨论固定导航、3D、图层透明度等能力变更。

该策略的默认取舍是：宁可少迁移一个视觉元素，也不改变既有业务语义。

## 5. 布局几何

### 5.1 桌面布局

| 区域 | 建议几何 | 约束 |
| --- | --- | --- |
| 一级顶栏 | 高 64px，横向全宽 | 位置、内容和浅色壳层保持现状 |
| 地图画布 | `100vw × calc(100vh - 64px)` | 不被固定左栏永久压缩 |
| 全局搜索 | 保留在一级顶栏既有位置 | 只迁移输入框的颜色、边界、圆角与状态，不改为新的地图业务搜索 |
| 图层入口 | 地图左上，距画布边缘 16px | 与其他地图工具对齐；打开左侧覆盖抽屉 |
| 图层抽屉 | 宽 320px；可在 300–336px 内微调；顶端位于地图画布顶部 | 覆盖地图，不推动画布；高度不超过可用画布高度 |
| 地图缩放组 | 地图左下或现有已验证位置，距边缘 16px | 放大、缩小组成一组，单项高 40px |
| 定位 / 复位 | 与缩放组间隔 8px 或 12px | 不添加鹰眼、收藏、3D、测量 |
| 信息浮层 | 建议宽 280–320px，最宽 360px | 只做对象预览或状态说明，不承载重复业务操作 |
| 右侧对象面板 | 建议宽 360px；可在 344–400px 内适配真实字段 | 仍是选中幢后的唯一操作中心；覆盖地图而非产生第二主栏 |
| 边缘安全区 | 16px；大型面板之间最少 16px | 避免控件贴边和彼此遮挡 |

在 1440px 与 1280px 宽度下，图层抽屉和右侧对象面板可以共存，但必须保证中间仍有足够地图上下文。1010px 宽度下，默认只保留一个高层面板：打开图层抽屉时可暂时收起对象面板，关闭后恢复此前状态；不能将两者压成不可读窄栏。

### 5.2 组件内部几何

- 主控件高度：32px；地图工具触控面积：40 × 40px；关键按钮最小触控面积：44 × 44px。
- 输入框内边距：水平 12px；图标与文字间距：8px。
- 面板标题区：高 48–56px，左右内边距 16px。
- 面板内容：16px 内边距；高密度树节点可使用水平 12px、垂直 8px。
- 图层树层级缩进：一级 0，二级 20px，三级 40px；缩进只表达结构，不用更小字号降级。
- 信息浮层标题与正文间距 8px，字段行间距 6px，分组间距 12px。
- 控件组内间距 4px，控件组之间 8–12px，独立悬浮面之间至少 16px。
- 不使用多个相邻但无语义的 18 / 20 / 22 / 24px 内边距值。

## 7. 地图底图处理

1. 保留当前单个离线 SVG、小区级演示范围、默认 Z17 和既有图层结构。
2. 将底图基础色统一为暖白陆地、蓝灰水体、灰白道路、灰色建筑和低饱和绿地。
3. 减少非任务要素的对比：道路支线、次要建筑轮廓和装饰纹理降低到次级层，不可直接隐藏真实图层。
4. 保证宗地边界、房屋幢、其他构筑物、道路、绿化、门牌和建筑编号仍能通过图层开关真实显隐。
5. 地图标签用 12px 以上字号、深灰文字和轻微白色外描边，避免用模糊阴影。
6. 水体与绿地只承担空间识别，不抢夺当前幢的蓝色选中焦点。
7. 选中时可弱化周边要素，但不低于 `0.56`，并保留必要的道路、幢号和空间关系。
8. Z16 / Z17 / Z18 下分别检查线宽、标签密度和选中描边；不要只对默认缩放级别优化。
9. 始终显示“演示底图 · 非测绘成果”，其可读性不得依赖悬停。

不要更换为在线地图、伪造真实测绘精度、增加不存在的城市级道路或行政数据，也不要把地图渲染性能问题掩盖为静态截图。

## 8. 关键组件

### 8.1 选中对象

- 默认态：建筑使用中性填充和轮廓，标签保持可读。
- 悬停态：使用 `--gis-map-hover-fill`，轮廓可提升到 1.5px；光标和焦点共同提示可选。
- 键盘焦点态：对象外侧显示 2px 主色焦点环和 2px 白色间隔，不能只改变颜色。
- 选中态：主色 2px 描边 + 24% 主色填充；现有业务状态色仍保留，必要时用外描边而非覆盖填充表达选择。
- 选中完成后：打开或更新右侧对象面板，地图视角和对象上下文按既有逻辑保存。
- 取消选择后：恢复底图状态并关闭对象面板；不清除无关图层设置。
- 定位标记：只在确有定位语义时出现，不把装饰性图钉永久叠在每栋建筑上。

### 8.2 信息浮层

信息浮层只承担快速预览，右侧对象面板继续承担完整信息和操作。

- 桌面悬停可显示轻量预览；键盘焦点触发相同内容；触屏不依赖悬停。
- 内容必须来自现有真实字段模型或已标注的模拟数据，禁止复制参考图字段。
- 推荐最多显示对象标题、2–3 个已存在的关键信息和一个“查看对象”入口；若该入口会复制右侧面板动作，则直接省略。
- 浮层优先出现在对象上方，保持 12px 间距；空间不足时自动翻转，并避免遮挡对象和地图工具。
- 指示箭头与浮层同色，不使用夸张气泡造型。
- 加载、无数据和错误均应在浮层内使用短文本反馈，不显示空白白框。

### 8.3 图层抽屉

- 使用左侧覆盖式 320px 面板，不能恢复固定左栏，也不能推动地图。
- 保留三级结构：图层组 → 业务图层 → 独立元素。
- 第二层支持整组开关和半选状态，第三层提供独立开关。
- 当前分组和业务名称沿用已有证据，不用参考图文案重命名。
- 行高建议 40px；展开图标、标签、开关分别对齐，整行可点击范围不少于 40px。
- 抽屉有明确标题和关闭按钮；关闭后焦点返回图层入口。
- 长列表只让内容区滚动，标题和必要操作保持可见。
- 参考图中的透明度滑块不得默认加入。只有现有需求已支持或用户另行批准时，才作为真实图层能力实现。
- 已备案、抵押、查封等继续属于业务状态图例，不迁入地图图层树。

### 8.4 搜索

- 保留一级顶栏中的智能搜索位置和语义，不把参考图的悬浮搜索条直接叠加到地图上。
- 输入高 36px 或沿用共享壳层既有高度；背景使用 `--gis-color-fill`，聚焦时切换白底、主色边界和焦点环。
- 占位文案只能说明真实支持的搜索范围，不能承诺不存在的地块、道路或地址检索。
- 清除按钮、提交按钮和快捷键提示仅在功能真实存在时出现。
- 结果列表必须支持键盘上下移动、Enter 选择、Escape 关闭，并用 `aria-activedescendant` 或等效可访问模式同步当前项。
- 无结果、加载、错误和结果过多时分别给出明确状态；不得把无结果伪装为空白列表。

### 8.5 地图工具

- 常驻工具只有图层、放大、缩小、定位和复位视角。
- 每个工具视觉盒 40 × 40px，实际触控热区至少 44 × 44px；图标建议 20px。
- 放大 / 缩小可成组，组内使用 1px 分隔线；定位和复位可独立分组。
- 按钮必须有可访问名称；只有图标时使用 `aria-label` 和悬停提示。
- 缩放到边界时禁用对应按钮；定位进行中显示进度，失败时给出非阻塞错误。
- 不增加 3D、鹰眼、收藏夹、框选、测量或底部操作条。

### 8.6 图标规范

- 全部使用同一套 SVG 线性图标；优先复用现有 TDesign / 共享组件资源。
- 常规图标 16px，地图工具 20px，强调性对象图标最大 24px。
- 建议使用 1.5–2px 线宽、圆角端点和一致 viewBox。
- 图标默认继承文字颜色，选中时使用主色，禁用时使用禁用色。
- 不混用 emoji、Unicode 几何字符、位图图标和多套线宽。
- 图标不能独自承担“错误 / 成功 / 图层已开”等关键信息，必须配合文字、形状或可访问名称。

## 9. 所有关键状态

| 对象 / 组件 | 必须覆盖的状态 | 验证重点 |
| --- | --- | --- |
| 地图画布 | 初始、加载、可交互、加载失败、空数据、离线演示 | 状态提示不遮挡核心工具；失败后仍可恢复 |
| 地图对象 | 默认、悬停、键盘焦点、选中、取消选中、不可用 | 选择不依赖颜色；业务色不被覆盖 |
| 对象面板 | 关闭、打开、切换对象、加载、无数据、错误 | 是唯一操作中心；切换不闪空白，不丢上下文 |
| 信息浮层 | 隐藏、悬停 / 焦点显示、翻转、加载、无数据、错误 | 不与对象面板争夺操作；Escape 可关闭 |
| 图层入口 | 默认、悬停、焦点、按下、已展开 | `aria-expanded` 与真实状态一致 |
| 图层抽屉 | 关闭、打开、滚动、关闭中、窄屏互斥 | 焦点进入与回收正确；不推动地图 |
| 图层组 | 全开、全关、半选、禁用、加载失败 | 父子状态同步；不能只靠颜色 |
| 搜索 | 空闲、输入、组合输入、加载、有结果、无结果、错误、已选择、清除 | 键盘路径完整；文案不承诺未实现范围 |
| 地图工具 | 默认、悬停、焦点、按下、禁用、进行中、成功、失败 | 视觉反馈与真实地图变化一致 |
| 定位 | 未授权、请求中、成功、拒绝、超时 / 失败 | 不假定浏览器权限；失败可重试 |
| 复位视角 | 可用、执行中、完成 | 恢复当前定义的默认视角，不清空图层设置 |
| 系统反馈 | 信息、成功、警告、错误 | 颜色之外有文字 / 图标；不伪造业务结论 |

状态实现应复用共享组件语法。不要为 GIS 单独发明按钮、输入、开关、抽屉、弹层或焦点样式。

## 10. 响应式与可访问性

### 10.1 响应式

- 1440 × 900：验证图层抽屉与对象面板并存、地图对象仍有足够空间。
- 1280 × 900：验证面板不遮挡关键对象和地图工具。
- 1010 × 900：图层抽屉与对象面板采用互斥或临时收起策略，禁止将中心地图压成窄缝。
- 390px：作品集页面不伪装成 GIS 手机产品。若原型需要窄屏兜底，只保留可阅读的地图快照 / 核心状态和独立打开桌面原型入口，且无横向溢出。
- 所有视口都要检查 `scrollWidth == clientWidth`；面板内部允许有自己的受控滚动区。

### 10.2 键盘与焦点

- 所有按钮、开关、树节点、搜索结果和可选地图对象可通过键盘到达。
- 焦点顺序按顶栏 → 地图入口 → 地图对象 / 工具 → 已打开面板排列，避免焦点跳入视觉上被遮挡的内容。
- 焦点环使用 2px 主色外环并留出可见间隔；不能用浏览器默认轮廓被 `overflow` 裁掉。
- Escape 关闭当前最高层浮层；关闭后将焦点还给触发控件。
- 抽屉或模态打开时按其语义管理焦点。模态需要背景 `inert`，普通非模态抽屉不得无故锁死地图。
- `aria-expanded`、`aria-checked`、半选状态、`aria-hidden` 与真实 UI 同步。

### 10.3 减弱动效

默认动效只用于解释状态变化：悬停 120ms，面板 180ms，地图过渡不超过 240ms。检测到 `prefers-reduced-motion: reduce` 时：

- 取消位移、缩放、弹性和视差效果。
- 面板改为即时显隐或极短淡入。
- 地图视角直接切换，保留最终状态反馈。
- 加载指示不要依赖连续旋转才能被理解，可配合文字。

## 11. 性能要求

- 不替换当前单个离线 SVG 为更重的在线依赖。
- 不为每个地图对象创建常驻阴影、滤镜或独立模糊层；优先使用共享样式和轻量描边。
- 对地图 `pointermove`、悬停命中和缩放更新使用节流或 `requestAnimationFrame`，避免同步反复布局。
- 面板开关只切换必要状态，不重新构建整个地图 DOM。
- 动画优先使用 `transform` 和 `opacity`，避免持续动画 `width`、`left`、复杂滤镜和大面积阴影。
- 图层隐藏应真实控制对应 SVG 分组，并保留状态，不复制多套 SVG。
- 搜索输入需要防抖时只防抖查询，不延迟输入回显。
- 图片与字体不得引入阻断首屏的外部请求；保持原型可离线预览。
- 在三个桌面视口检查操作期间是否有明显掉帧、面板闪动、地图重排和焦点丢失。

## 12. 实施步骤

### 步骤 1：建立回归清单

记录改造前的默认视角、Z16 / Z17 / Z18、六类图层开关、选幢、对象面板、进入 Building View、进入 Task View、返回地图、定位和复位状态。保存一组 1440、1280、1010px 基线截图。

### 步骤 2：盘点并映射 Tokens

检查现有 `tdesign-tokens.css`、`system.css` 和 `workspace-tdesign.css`。把本指南中的 GIS token 映射到已有变量；只为确实缺少的地图语义新增变量。先替换重复硬编码，再改组件外观。

### 步骤 3：改造地图底图

按“陆地 → 水体 / 绿化 → 道路 → 建筑 / 宗地 → 标签 → 选中对象”的顺序调整 SVG 样式。每完成一层，就在三个缩放级别验证对比度、图层显隐和标签可读性。

### 步骤 4：统一悬浮表面

统一搜索、地图工具、信息浮层、图层抽屉和对象面板的白色背景、1px 边界、圆角、阴影和间距。检查是否存在多套相近值，并收敛到语义 token。

### 步骤 5：改造对象交互

实现默认、悬停、键盘焦点、选中、切换和取消选中视觉。确保选中描边不覆盖业务色，选中后仍由右侧对象面板承载操作。

### 步骤 6：改造图层、搜索和地图工具

保持原能力和 DOM 语义，仅调整布局与状态表现。确认图层真实控制 SVG、搜索范围不扩写、地图工具不增项。

### 步骤 7：补齐状态与可访问性

逐项覆盖第 9 节状态表；验证 Tab、Shift+Tab、Enter、Space、方向键和 Escape。检查焦点回收、半选、加载、错误、空状态和减弱动效。

### 步骤 8：做视口和性能回归

在 1010 × 900、1280 × 900、1440 × 900 实际预览；同时验证 390px 的作品集兜底呈现。确认无横向溢出、地图视图真实变化、深链和返回上下文未回退。

### 步骤 9：更新展示证据

只有原型验证通过后才重拍作品集截图。截图应展示真实已实现状态，并保留模拟数据 / 非测绘成果说明；不能用静态画面掩盖失效交互。

## 17. 依据与优先级

本指南依据以下材料整理：

1. `UI_DESIGN_BASELINE.md`：当前有效的页面、组件、业务原型和发布规则，视觉实施时优先级最高。
2. `CURRENT_BASELINE.md`：项目事实、证据边界、三层架构和当前实现状态。
3. `PRODUCT.md`：作品集目标、产品边界、品牌承诺与可访问性要求。
4. `portfolio-site-handoff/CASE_PAGE_INTEGRATION_NOTES.md`：案例页迁移边界、间距问题和验证视口。
5. 用户提供的参考图：只用于视觉观察，不作为业务、字段、数据或功能依据。

当材料发生冲突时，先遵守业务与证据边界，再遵守当前 UI 基线，最后才采用参考图的视觉特征。
