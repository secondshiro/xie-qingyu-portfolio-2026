# 执行网查询助手：人工验证与批量工作流设计

> 日期：2026-09-10  
> 状态：用户已授权执行  
> 取代：`2026-09-10-execution-query-production-tool-and-case-design.md` 中“两类验证码均自动通过”的前置条件

## 1. 产品判断

新版不再把“解决验证码”当成产品主体。验证码是目标站用来要求真人介入的边界，工具将如实保留这个边界，并聚焦验证前后的重复工作：批量输入、逐项调度、自动接续、详情整理、历史比较和 Excel 导出。

这不是对旧工具的降级。目标站的公开页面脚本已确认：验证通过后，`captchaId` 与 `pCode` 会保留在当前页面，搜索、翻页和详情都复用该票据，只有服务端判定过期时才重新验证。因此一次人工验证可以支撑后续多项查询，而不需要每项都跑高耗时 OCR。

## 2. 范围与非目标

### 本轮交付

1. Chrome 伴侣遇到任何交互验证时停止自动操作，清楚提示用户在页面完成验证。
2. 伴侣通过页面内已验证票据判断是否可继续，不根据弹窗瞬时消失猜测成功。
3. 当前票据有效时，后续主体直接查询，不等待不存在的验证弹窗。
4. 侧栏支持逐行粘贴批量主体，可选身份或机构代码，去重并显示队列进度。
5. FastAPI 保存本地任务、项目状态和查询记录，失败不得写成“无记录”。
6. 任务结束后导出 `.xlsx`，至少包含“查询汇总”“案件明细”“未完成”三张表。
7. 保留可追溯的旧版功能与迭代叙事，为作品集页提供真实证据。

### 暂不实现

- 任何类型验证码的自动求解、自动刷新或第三方打码服务。
- 完全无人值守的定时查询。
- 云端同步、多人权限和对目标站私有接口的绕行。
- 未经用户明确选择的身份信息对外分发。

## 3. 交互流程

1. 用户在伴侣侧栏粘贴多个主体，每行格式为 `姓名或名称,身份或机构代码`，第二列可空。
2. 工具去除空行和重复项，预览有效主体数后创建本地任务。
3. 扩展在同一执行网标签中逐项填写并提交。
4. 若已有有效票据，直接等待结果。若弹出验证，侧栏显示“请在执行网完成安全验证”，用户完成后自动继续。
5. 工具读取列表和详情，将当前项写成有记录、确认无记录或明确失败。
6. 批量继续处理下一项。页面变化或验证等待超时时暂停整批，保留已完成结果。
7. 用户导出本次任务，或从本地历史中查看已有任务。

## 4. 状态语义

| 状态 | 用户看到的文案 | 后续行为 |
| --- | --- | --- |
| `queued` | 等待查询 | 继续排队 |
| `awaiting_verification` | 请完成安全验证 | 等待真人操作 |
| `searching` | 正在查询 | 等待页面结果 |
| `fetching_details` | 正在整理详情 | 逐条读取 |
| `completed_with_records` | 已完成，有记录 | 可查看和导出 |
| `completed_no_records` | 已完成，无记录 | 可导出 |
| `verification_timeout` | 等待验证超时 | 暂停批量 |
| `site_changed` | 执行网页面已变化 | 停止批量并更新适配 |
| `network_failed` | 连接失败 | 保留任务，可重试 |
| `cancelled` | 已取消 | 不删除已完成结果 |

有记录、无记录和失败是三个不可合并的结果。

## 5. 数据与隐私

- SQLite 只写入主体、任务状态、列表与详情、时间和失败分类。
- 验证码图片、提示字、坐标、`captchaId` 和 `pCode` 不持久化。
- Chrome 扩展不使用 `chrome.storage`，不申请 Cookie、历史或下载记录权限。
- 导出文件仅由用户点击生成，作品集只使用另行制作的脱敏样例。

## 6. Excel 输出

首版工作簿保持三张表：

- `查询汇总`：一行一个主体，包含状态、记录数、已读详情数、查询时间和失败原因。
- `案件明细`：一行一条记录，固定字段在前，其他详情字段按稳定表头展开。
- `未完成`：只收录失败、超时和取消项，保留可重试原因。

编号、身份码、案号按文本存储，防止 Excel 改写。表头固定、首行冻结、自动筛选，不添加与任务无关的仪表盘或计分。

## 7. 定时任务边界

定时能力放在批量、存储和导出稳定之后。它只创建待执行任务并提醒用户打开执行网和完成验证，不在用户不知情时操作网站。这一限制要在界面和作品集中直说。

## 8. 作品集叙事调整

案例的关键决策不再是“我如何破解新验证码”，而是“我如何重画自动化边界”。真实迭代证据包括：

1. 旧版从单次查询到批量、历史对比、截图和 Excel 的演进。
2. 目标站验证方式变化后，旧请求链路为什么失效。
3. 真实验证码试验的资源与稳定性成本，以及停止继续训练的产品判断。
4. 验证票据复用、人工接管与批量自动接续组成的人机协作流程。
5. 失败不冒充无记录、生产数据不进作品集的信任边界。

案例可以在“批量任务、人工验证自动接续、列表与详情、Excel 导出”经真实测试后进入公开页面。不声称完全自动、无人值守或长期兼容第三方网站。

## 9. 验收标准

- 自动化测试证明扩展不再请求验证码图片、不执行鼠标验证动作、不需要 `debugger` 权限。
- 真实 Chrome 中，人工完成一次验证后查询自动继续。
- 在票据未过期时执行第二个主体，不再弹出验证并得到明确结果。
- 批量队列中任一项失败不会覆盖已成功结果，验证超时会暂停而不是循环刷新。
- Excel 的三张表、列顺序、文本编号和空值处理与固定预期一致。
- 扩展、FastAPI 和作品集全部相关测试通过，临时验证码图片已删除。
