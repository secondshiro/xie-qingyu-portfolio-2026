# 个人作品集网站改造设计规格

历史规格，记录 2026-09-02 首版设计。首页大图、项目数量和定位已由后续改动取代，当前结构见 [文档索引](../../README.md)，视觉合同见 [DESIGN.md](../../../DESIGN.md)。

> 日期：2026-09-02  
> 状态：已实现并验证  
> 范围：首页 + 房产 GIS 作品说明页 + 必要的共享站点层  
> 已批准视觉稿：`.impeccable/mocks/homepage/unfolding-folio-b.webp`

## 1. 目标

建立一套可扩展的个人作品集网站首版，使访问者能够在短时间内：

1. 理解谢擎宇的定位是“AI 原生产品体验设计师”。
2. 看到真实产品工作，而不是先阅读长履历。
3. 进入房产 GIS 完整案例，理解问题、依据、设计判断、方案和证据边界。
4. 通过公开邮箱 `second988@qq.com` 发起联系。

网站不以政企或传统信息化服务商为目标受众。过去项目经验将被转译为复杂系统设计、跨端体验、视觉系统和 AI 协作能力。

## 2. 范围与非目标

### 本次包含

- Astro 静态站点基础结构。
- 自我介绍与作品索引合一的首页。
- 房产 GIS 作品说明页迁移。
- 共享导航、页尾、设计变量、布局组件、媒体舞台和响应式规则。
- 将原项目所需的公开安全素材和三个互动原型复制到新站目录。
- 桌面与移动端验证、静态构建、链接检查和基本可访问性检查。
- GIS 系统改造指南作为独立交接材料。

### 本次不包含

- 修改用户提供的源 HTML、源素材或源原型。
- 扩建房产 GIS 的业务功能、后端、数据库、权限或部署工程。
- 补写不存在的用户研究、业务指标、上线结果或项目成果。
- 为简历中的其他项目虚构完整案例。
- 把生成式视觉稿中的 GIS 数据或界面字段当作真实产品内容。
- 直接改造原 GIS 产品视觉；该任务由独立指南交给其他 Agent。

## 3. 站点信息架构

### `/`

首页同时承担个人介绍和作品索引：

1. 紧凑站点导航。
2. 个人定位、价值主张和邮箱。
3. 房产 GIS 宽幅作品舞台。
4. 房产 GIS 项目标题、角色、范围和进入完整案例的入口。
5. AI 工作流与工具的低权重框架，只展示简历中已确认的能力，不创建虚假详情链接。
6. 简短经历与能力摘要。
7. 邮箱联系和页尾。

### `/work/real-estate-gis/`

房产 GIS 作品说明页：

1. 站点级导航。
2. 案例标题、摘要、角色、输入、贡献、输出和证据边界。
3. 首屏后立即展示真实最终产品画面或互动总图原型。
4. 项目源头与证据方法。
5. 问题与设计机会。
6. 行业参照与设计判断。
7. “空间—对象—任务”三个工作面。
8. 三个关键设计取舍。
9. 价值假设与待验证边界。
10. AI 协作与人工判断。
11. 返回作品索引和联系入口。

站点导航与案例内部章节导航必须区分层级。案例页不复制产品顶栏，也不把内部锚点伪装成全站栏目。

## 4. 技术架构

使用 Astro 输出纯静态站点，避免为首版引入不必要的客户端框架。

建议目录：

```text
作品集网站/
├── PRODUCT.md
├── astro.config.mjs
├── package.json
├── public/
│   └── projects/real-estate-gis/
│       ├── media/
│       └── prototypes/
├── src/
│   ├── components/
│   │   ├── SiteNav.astro
│   │   ├── SiteFooter.astro
│   │   ├── ProjectFold.astro
│   │   ├── CaseHero.astro
│   │   ├── CaseSection.astro
│   │   ├── CaseToc.astro
│   │   ├── MediaStage.astro
│   │   └── PrototypeFrame.astro
│   ├── layouts/
│   │   └── SiteLayout.astro
│   ├── pages/
│   │   ├── index.astro
│   │   └── work/real-estate-gis.astro
│   └── styles/
│       ├── tokens.css
│       ├── global.css
│       └── case-study.css
└── docs/
    ├── briefs/
    ├── guides/
    └── superpowers/
```

组件边界：

- `SiteLayout` 只负责文档壳层、元信息和全站样式。
- `SiteNav` 与 `SiteFooter` 只承担站点关系。
- `ProjectFold` 管理首页连续折页项目段，不包含项目业务逻辑。
- `CaseHero` 管理案例摘要和事实列表。
- `CaseSection` 管理统一章节节奏，不允许子组件再叠加同等级外边距。
- `CaseToc` 管理唯一的页面级吸附目录、当前章节状态和移动橙点。
- `MediaStage` 统一图片、视频、SVG 和图注的呈现。
- `PrototypeFrame` 管理 iframe、加载状态、失败回退、完整页面入口与窄屏降级。

## 5. 内容与数据流

- 首页内容来自 `PRODUCT.md` 和简历中的已确认事实。
- 房产 GIS 内容来自原案例页、`UI_DESIGN_BASELINE.md` 和 `CURRENT_BASELINE.md`。
- 案例文字可重新分组和缩短，但不得改变事实含义或证据等级。
- 所有媒体在构建时引用新站 `public/` 中的复制品，不跨目录依赖源项目。
- 三个原型在新站内使用稳定相对路径；只调整复制品中的路径，不修改源文件。
- iframe 加载失败时保留静态证据、简短说明和“打开完整原型”入口。
- 390px 下不嵌入桌面业务原型；显示静态证据并提供独立打开入口。

## 6. 视觉系统

### 视觉世界

采用“展开式作品册”：网站像一份连续展开的产品设计专刊。每一折承担一个明确阅读任务，项目画面从页面色面中展开，而不是被装进重复卡片。

### 色彩

- 页面背景：`#F7F7F4`
- 主文字：`#26251E`
- 柔和石色：`#E8E6E0`
- 次级模块：`#EEEDE8`
- 交互强调：`#F54E00`
- 常用边界：`rgba(38,37,30,.10)`，只在控件和必要分层中使用。

房产产品蓝只存在于真实截图、原型和必要证据中，不进入站点导航、标题或装饰系统。

### 字体与层级

使用本地系统无衬线：

```css
font-family: system-ui, -apple-system, BlinkMacSystemFont,
  "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
```

- 首页主标题：桌面 44–52px，移动端 34–40px。
- 案例主标题：桌面固定 44px，45rem 以下固定 40px，字重 400，最多两行。
- 一级章节标题：固定 26px / 400；章节导语：固定 20px / 400，以字号和灰度形成一档层级差，不随宽屏放大。
- 工作面标题：固定 18px / 500；其他卡片 / 模块标题 18–22px。
- 正文：16px，行高 1.6。
- 图注与来源：12–14px。

不使用衬线标题、全大写装饰段落或极端巨型营销字号。

### 容器与栅格

- 站点主容器最大宽度 1320px。
- 桌面水平页边距 32–48px；移动端 16–20px。
- 正文阅读列最大约 720px。
- 案例章节统一使用 160px 标签列 + 弹性正文 / 媒体列。
- 标题、导语和章节内容共享弹性正文列，不再额外套 720px 宽度。
- 只有媒体舞台可以按明确规则突破正文列。
- 不再保留 `--wide`、`--content`、`.inner`、`.resultInner` 等竞争容器。

### 间距

- 微间距：4 / 8px。
- 组件内部：12 / 16px。
- 内容组：24 / 32px。
- 模块间：48 / 64px。
- 章节间：80 / 96 / 120px。

相邻距离只由父级 `gap / padding` 或子级 `margin` 的一方负责。标题组件不管理与下一模块的距离。

### 表面与边界

- 主要层级依赖柔和实色、留白、尺度和轻微重叠。
- 避免重复的描边卡片、表格化章节分隔和全页细线栅格。
- 阴影只用于折页重叠和真正悬浮媒体，保持浅且宽。
- 圆角克制：媒体与大色面 8–12px，按钮 4–6px；不使用胶囊化泛滥。

## 7. 已批准首页构图

批准稿：`.impeccable/mocks/homepage/unfolding-folio-b.webp`。

首屏结构：

1. 52px 紧凑导航。
2. 上部约 40%：左对齐中等尺度标题、副句和邮箱。
3. 下部约 60%：无设备框的宽幅 GIS 产品画面。
4. 页面折缝处只使用一条细小橙色标记。
5. 第二折只露出“房产 GIS 体验重构”和“空间 → 对象 → 任务”。

生成稿中的 GIS 界面是构图占位。正式首页必须替换为源项目真实公开安全素材，不使用生成稿中的字段、地图或数据。

## 8. 案例页迁移规则

- 保留原案例的证据结构、三层产品架构、三个高光工作面、关键取舍、价值边界和 AI 协作说明。
- 用亮色、柔和色面和大型产品画面替换旧页深色工作区、密集线框和叠加间距。
- 每一屏只承担一个阅读任务；文字围绕证据组织，不把图片降为装饰。
- 项目事实集中在案例首屏；最终产品结果在首屏后立即出现。
- 静态证据、互动原型和事实说明使用不同标签，避免用户误认。
- 不使用生成式 GIS 视觉稿替换真实证据。
- 不把产品内部 TDesign 视觉改成网站视觉。

## 9. 交互与动效

- 导航保持紧凑，可在滚动后使用不透明暖白背景和极轻阴影。
- 首页只使用一个主要动效：产品宽幅画面随滚动从页面下缘轻微展开。
- 项目链接悬停通过色面位移、图像轻微缩放或橙色标记移动表达，三者最多选其一为主动作。
- 案例图片默认静态，视频和原型由用户主动播放或操作。
- 案例只保留一个页面级吸附目录。目录含简短案例标题，14px 紧凑树状分支；默认、悬停、当前文字使用 40% / 60% / 75% 主文字，单个 6px 橙点移动到当前文本右侧。
- `prefers-reduced-motion: reduce` 下取消位移、缩放和视差，只保留即时状态变化。
- 所有入口至少 44px 可操作高度；焦点状态不能依赖颜色变化。

## 10. 响应式行为

### 1440 / 1280px

- 保留首页 40% 文字 + 60% 宽幅产品舞台的纵向节奏。
- 案例章节标签列与正文列稳定对齐。

### 1010px

- 首页画面仍保持全宽，文字区缩短但不压缩标题到异常换行。
- 案例双列内容可转为单列，媒体保持最大可读宽度。

### 390px

- 导航收口为姓名、作品入口和邮箱，保证键盘与触控可达。
- 标题先出现，GIS 静态画面随后完整显示；取消透视折页和大面积重叠。
- 案例章节全部单列，标签变为章节上方的小号标记。
- 隐藏 iframe，保留静态证据和独立原型入口。
- 页面不得横向滚动。

## 11. 错误处理与降级

- 图片加载失败：保留定比例背景、替代文本和图注，不造成布局坍塌。
- iframe 加载失败：显示静态画面、失败说明和新窗口入口。
- JavaScript 不可用：首页和案例正文、图片、链接仍可阅读和导航。
- 原型只支持桌面时，在窄屏明确说明并提供外部打开，不伪装手机版本。
- 外部行业参考链接使用 `rel="noopener noreferrer"`，失效不影响主叙事。

## 12. 可访问性

- 语义化标题层级，每页只有一个 `h1`。
- 提供跳到主内容链接。
- 当前导航、案例章节和原型入口使用清楚的可访问名称。
- 文字、链接和焦点状态满足可读对比；重点不只靠橙色表达。
- 图片提供描述内容和论点的 `alt`，纯装饰图使用空 `alt`。
- iframe 有准确 `title`，并提供等价静态证据与完整页面入口。
- 动效遵守减弱动效设置。

## 13. 验证策略

### 构建与结构

- 安装依赖后运行 Astro 类型 / 内容检查和静态构建。
- 检查所有本地图片、视频、CSS、iframe 与深链路径。
- 检查构建产物不引用源项目绝对路径。
- 检查生成产物中保留方向合同注释。

### 视觉

- 一次批量捕获 1440、1280、1010 和 390px。
- 检查首屏与批准稿的结构、尺度、色面和产品画面比例。
- 检查长案例的章节节奏、媒体比例、文字换行和无横向溢出。
- 第一批问题一次性修正，再进行最多一次确认轮。

### 行为

- 键盘验证导航、项目入口、案例锚点、原型入口和页尾邮箱。
- 验证三个互动原型及其深链参数。
- 验证窄屏 iframe 降级。
- 验证减弱动效。
- 运行现有案例叙事与公开安全检查，并补充新站链接检查。

OWN-WORLD: 暖白与柔和石色色面、墨色无衬线、克制橙色折页标记、大型无设备框产品画面、极少边界。

## 15. 交付标准

- 首页和案例页职责清楚。
- 首页第一视口符合批准构图的结构与尺度关系。

- 站点视觉不被房产产品蓝和深色工作区绑架。
- 页面只有一套主容器和明确的媒体突破规则。
- 源文件保持未修改，新站在当前项目目录中可独立构建。
- 1440、1280、1010 和 390px 无横向溢出。
- 键盘、焦点、减弱动效和媒体降级有效。
- 公开构建不包含不安全素材或源项目绝对路径。
- Impeccable 检测、截图审查、完成审查和 `DESIGN.md` 记录均完成。
