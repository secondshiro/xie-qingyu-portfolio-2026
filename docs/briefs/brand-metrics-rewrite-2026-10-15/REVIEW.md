## 验证

顺序运行。跑前把 `dist` 与 `test-results/` 移出工作区，并确认 4331 端口没有遗留预览进程。原因有两个，一是 `astro build` 每次会删自己的 `dist/.prerender/.vite/`，该目录会积累到正好 50 个文件而触发 WorkBuddy 沙箱的批量删除保护，构建直接失败；二是 Playwright 启动时会清理 `test-results/`，同样会撞上该保护。移出用 `mv`，不要用 `rm`。

- `npm test`，7/7 通过。
- `npm run build`，5 页构建完成，0 错误、0 警告，保留 1 条既有临时脚本类型提示（`artifacts/interview-2026-10-09/director/video.mjs`，与 `src/` 无关）。
- `npm run test:e2e -- --workers=1`，81 通过、4 失败。失败的 4 项是房产 GIS、AI 评审与品牌系统的键盘往返，以及触屏封套单点，均卡在 `transitionProbe.phases` 断言与触屏跳转超时，与 2026-10-15 前几轮记录属同一族，本轮未改转场代码与测试。

**失败项的波动说明。** 这一族检查在三轮全量运行里分别给出 79 / 80 / 81 通过，失败落在 4 至 6 项之间，成员在四个案例的键盘往返与触屏封套之间轮换，执行网助手的键盘往返本轮通过、房产 GIS 的转场遮盖项只在首次出现。其中「房产 GIS 1440px 点击先遮住旧页」单独复跑该测试文件为 8/8 全过，可确认与本次改动无关。本轮改动只涉及文案与一处主屏文字，未触碰转场脚本与样式。

`astro build` 在本轮连续两次在预渲染阶段失败（残留的 `dist/.prerender` 使新构建引用不到旧 chunk），因此最后一次全量运行改用「先构建一次、再让 Playwright 复用该静态服务」的方式，临时配置在 `artifacts/brand-rewrite-20261015/playwright.reuse.config.ts`（不纳入版本库），测试文件、断言与超时设置均与根配置一致，只替换了静态服务的提供方式。
