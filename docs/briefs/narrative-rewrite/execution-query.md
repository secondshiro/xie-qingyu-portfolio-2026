# 执行网查询助手连续样稿

律师会把需要持续复核的姓名或机构名称整理成名单，逐项查看执行记录和案件详情，再和上一次查询结果比较。名单只有一两项时，人工操作还能应付。名单变长以后，等待、翻页、抄录和排表会在每个主体上重复一次。

我从四代旧工具、查询历史和 Excel 使用痕迹里重建这项工作。早期版本先跑通单次查询，随后加入批量和历史比较，又修正了新增与撤销的状态颜色。第四版可以保存详情、截图和 Excel，也把请求、网站适配和界面绑在了一起。版本变化说明使用者一直需要批量处理和复核记录，也说明旧架构已经很难继续维护。

网站后来把字符图片验证换成随机滑块和文字点选。列表、翻页和详情开始依赖浏览器页面里的短时状态，旧请求链随之失效。我试过本地图像识别，也检查过开源方案。旋转字形、行为校验和持续调参带来的资源开销不断增加，仍不足以支撑一批日常查询。

我把验收目标改成整批任务能否可靠完成。安全验证固定由人在执行网页面完成，工具继续承担名单整理、逐项调度、列表与详情读取、历史保存和 Excel 导出。这样保留了网站要求的真人操作，也让重复劳动继续由工具接手。

当前产品从本地控制台开始。浏览器桥梁自动打开或复用执行网查询页，遇到验证时把官网带到前台。用户完成一次操作后，工具继续当前项和余下名单。本地记录把结果分成有记录、无记录和未完成。无记录表示网站完成查询并返回明确空结果，未完成表示验证超时、页面变化或连接失败，查询结论还不存在。

历史比较只使用成功快照。同一主体再次查询后，工具区分首次记录、新增、存续和本次未见。任何未完成项都不会进入比较。导出的查询汇总、案件明细和未完成项分在三张工作表里，使用者可以直接筛选和逐项核对，少做网页上的抄录和重新排表。结果怎样使用仍由律师判断。

2026 年 9 月 12 日，我用两项合成任务检查了一次真实浏览器流程。用户完成一次文字点选验证后，第一项保存了列表与一条详情，第二项复用同一页面会话并确认无记录。整批两项全部完成，三张工作表通过结构、公式错误和视觉检查。

这次小样本证明当前网站下的人工接续、会话复用、详情读取和导出可以连起来。它没有证明无人值守或长期兼容。目标网站再次调整页面与验证流程时，维护者仍要先核对页面合同，再决定能否继续任务。
